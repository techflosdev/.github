# Support

Welcome to **techflows**. This document explains how to get help and where to ask questions.

## Before you ask

1. Check the **README** and docs in the specific repository.
2. Search existing **Issues** and **Discussions** for the same topic.
3. Confirm you are on a supported version (latest release or `main`).

## Where to go

| Need | Channel |
| --- | --- |
| Bug report | GitHub Issue using the **Bug report** template |
| Feature idea | GitHub Issue using the **Feature request** template |
| How-do-I / discussion | Repository Discussions (if enabled) or a question-labeled issue |
| Security vulnerability | See [SECURITY.md](./SECURITY.md) — do **not** file a public issue |
| Code of Conduct concern | See [CODE_OF_CONDUCT.md](./CODE_OF_CONDUCT.md) |
| Org / website | [https://www.techflows.app/](https://www.techflows.app/) |

## Response expectations

We are a small open-source organization (~dozens of collaborators). Maintainers triage issues as capacity allows. Labeling (`needs-triage`, `bug`, `enhancement`, etc.) helps us prioritize.

- **Critical security**: see SECURITY.md SLAs
- **Bugs with reproduction**: higher priority than unreproducible reports
- **Features**: evaluated against roadmap and maintenance cost

## What we cannot provide

- Guaranteed paid support or SLAs on free public repos
- Private consulting via GitHub Issues
- Support for unofficial forks or modified builds we did not publish

## Commercial / partnership

For partnership or commercial inquiries related to techflows products, use contact options on [techflows.app](https://www.techflows.app/).
